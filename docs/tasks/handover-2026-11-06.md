## Where the real work stands

**The goal is the I2 prototype, not a redesign.** The supersprint `tydzien-2` decision, approved by
Justyna on 2026-10-30, is to build a clickable prototype of idea I2 and keep researching — not to
roll anything out. Acceptance criteria are already written in
[candidate-scope-card-assistant.md](candidate-scope-card-assistant.md); read that file first.

In short: a candidate-side assistant asks about a vague answer ("Co dokladnie zrobiles sam? Jaki
byl efekt? Skad wiesz, ze zadzialalo?") and composes a fixed-structure card — _Moja czesc / Co
robil zespol / Efekt / Jak to sprawdzono_ — which the candidate approves or corrects. The recruiter
sees that card at the top of the application with a count of concrete facts. Course deadline is
about 2026-11-23.

The chain behind it: outcome = companies that bought in month M buy again within 90 days, 30% ->
60%, with ~45% as the first milestone; the drop-off is between the draft of the next ad and payment
(49% -> 35%); opportunity O01 = the recruiter cannot tell from an application what the candidate did
themselves (PRES 16, the only thread that changed in June 2026). Experiment E2 would measure
payment but needs the real DoRoboty team and 3-4 months, so it stays a plan.

Justyna's own documents already record two caveats worth keeping in view: S20 undermined the simple
version of I2, and S18 suggests the draft timing is a system rule rather than a company decision,
which weakens the "80% of companies start a draft" figure that the draft-to-payment framing rests
on. The prototype should therefore be built so its central claim can fail visibly — the Kuba vs
Natalia check below is that test, and it must be able to come out negative.

### What is known from SKILL.md, so it need not be re-derived

Space Grotesk 400/500/700 for headings and body; IBM Plex Mono 400/500 for anything that is data —
labels, prices, units, dates, locations, counters, score, status. Radii 6px for buttons and fields,
999px for choice elements and tags, 14px for pricing cards; shape carries meaning, so a pill means
"choose" and a 6px rectangle means "do". Depth from paper tones and 1px lines, never blurred
shadows. Lists are rows separated by 1px lines, not a grid of cards. Content width matches the
landing, max 1080px, prose to about 62 characters. Motion only for control state changes, 120-200ms,
disabled under `prefers-reduced-motion`. Dark `--panel` sections belong to marketing, not product.
Product headings are smaller than the landing's: page title about 32px, section 20px.

The only exact value given is the signal orange `#FF4A1C`, which has 2.9:1 contrast on paper and so
must never be letter color on a light background. It has exactly five roles: one signal action per
view at most, a header accent, marking a default choice, marking a change or novelty, and focus.
Token names without values: `--paper`, `--ink`, `--ink-2`, `--muted`, `--line`, `--signal`,
`--signal-text`, `--signal-ink`, `--panel`, `--danger`. The type scale and spacing scale are in the
missing files.

Content honesty rules from the skill: the match score is a reading order derived from text, not a
best-candidate verdict, shown as a mono number such as `74 /100`, with no bars or color, a note on
the method's limits above the list and always an alternative ordering. The phrases "najlepszy
kandydat", "gwarancja trafnego wyboru" and "AI wybierze za Ciebie" are forbidden. Demo numbers,
prices and companies must be marked as demo. Build / Apply / Lead categories get no color.

One conflict to resolve when the conversion starts: the skill loads fonts from Google Fonts, while
this project forbids remote runtime requests and bundles its fonts locally. The fonts will have to
be bundled.
